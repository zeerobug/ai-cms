# AICMS — multi-tenant CMS with built-in AI

Each site (tenant) can:

- **Ask AI to write an article** on any topic. Whether the article goes live straight away or waits for review is set by that site's **AI policy**.
- **Ask AI to design the site** ("a calm Japanese-inspired look, serif headings, magazine homepage"). The AI fills in a theme spec for a **template system shared by every site**, so every generated look is safe, responsive and works with any content.
- Optionally give **one article its own AI-designed look**.
- Add **images** to the home page hero and to articles (a cover image, plus images inside the body), either **uploaded** or **generated by AI**. Claude only writes text, so AI images come from OpenAI's image API, or from the offline mock, which draws a gradient.
- Get **SEO handled automatically**. Every public page has a canonical URL, Open Graph and Twitter tags, and schema.org JSON-LD. Each site serves its own `sitemap.xml` and `robots.txt`. The AI writes the search title, meta description and slug for its own articles. When an article is published with any of these missing (search title, description, tags or image alt text), the AI fills in the gaps. Editors can also ask the AI to rewrite one article's metadata, fill in every published article at once, or write the home page description.

## Quick start

```bash
npm install
npm run seed      # demo sites "demo" (AI may auto-publish) and "acme" (AI output needs review)
npm run dev       # http://localhost:3000/admin  — admin@example.com / password123
npm run build     # build the React admin for production (then `npm start`)
```

Without an API key the app runs a **mock AI** (offline, gives placeholder text). To use Claude:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
npm run dev
```

| Env var | Default | Purpose |
|---|---|---|
| `AI_PROVIDER` | `anthropic` if a key is set, else `mock` | Platform default AI backend (each site can pick its own provider and API key in Settings) |
| `AI_MODEL` | `claude-opus-5-5` | Default model for new sites (each site can override it) |
| `OPENAI_IMAGE_MODEL` | `gpt-image-2` | Model for AI images. Sites on OpenAI use their own key. When `OPENAI_API_KEY` is set, sites on Claude use it for images |
| `DB_PATH` | `data/aicms.sqlite` | SQLite file |
| `BASE_DOMAIN` | – | Turns on subdomain tenancy: `acme.example.com` → site `acme` |
| `APP_SECRET` | random | Signs CSRF tokens and encrypts sites' stored AI API keys; set it in production (changing it means keys must be re-entered) |
| `PORT` | `3000` | |

## How it fits together

```
src/
  themes/spec.ts      ThemeSpec: design tokens + a fixed set of layout choices; presets; normalizeTheme()
  themes/render.ts    The ONE layout engine + base stylesheet used by every theme
  content/blocks.ts   Articles are typed blocks (heading, paragraph, list, quote, code, callout, image…)
                      plus a Markdown <-> blocks converter for human editing
  content/media.ts    Image checks (PNG/JPEG/WebP/GIF by magic bytes) and allowed image URLs
  content/seo.ts      SEO rules: what metadata is missing, and merging AI suggestions (fill vs replace)
  web/media.ts        Serves uploaded / AI images at /media/<site>/<file>
  ai/provider.ts      AIProvider interface + article schema
  ai/anthropic.ts     Claude: structured outputs (Zod), adaptive thinking, effort, refusal fallbacks
  ai/mock.ts          Offline generator for demos and tests
  ai/service.ts       Policy checks, background jobs, saving results per site settings
  tenancy.ts          Roles, permissions, per-site settings schema, publish/apply decisions
  repo.ts             SQLite data access (every query is scoped by tenant_id)
  web/site.ts         Public sites: custom domain, subdomain or /s/<slug>
  web/admin-api.ts    JSON API behind the admin (dashboard, articles, design, settings, members, API tokens)
  web/admin-spa.ts    Serves the React admin (Vite dev middleware / built files)
  web/api.ts          REST API with bearer tokens for each site
admin/                React admin (React Router, one lazily loaded chunk per page)
```

### Template system
A theme is JSON only: colors, fonts (from a fixed list), type scale, radius, card style, density, header style (`left | centered | split | minimal | bold-band`), home layout (`grid | list | magazine | cards | minimal`), article layout (`classic | wide | sidebar` with a table of contents), hero, background texture, nav and footer. `render.ts` turns that into CSS variables and modifier classes on the same markup. The AI never writes HTML or CSS. Its output is checked against a schema and out-of-range values are clamped, so a bad generation cannot break a site.

### AI policy (per site, Settings page)
- AI on/off, model, effort, and the lowest role allowed to use AI
- **Allow AI to publish articles directly**, plus the lowest role that may request it. When this is off, AI articles go to the *review* queue.
- **Allow AI themes to be applied immediately**, plus the lowest role. When this is off, themes are saved for someone to preview and apply.
- Monthly AI article limit, language, default tone and length, and **brand voice** (sent with every request)
- Monthly AI image limit
- **SEO**: let the AI fill in missing metadata when an article is published (on by default; it only fills empty fields and never changes a published URL), and a monthly limit on AI SEO jobs. The site's own SEO settings cover the home page description, the content language code (`<html lang>`) and whether search engines may index the site.

### Static publishing (Netlify)
Each site can also be published as a static site on Netlify (**Publish** tab). Create an empty site in Netlify (*Add new site → Deploy manually*). Then, as the site's owner, enter its site ID and a Netlify personal access token. The token is stored encrypted, like the sites' AI keys.

- The export holds the same pages the server renders: home, articles, tag pages, RSS, `sitemap.xml`, `robots.txt`, a 404 page and the images those pages use. Canonical URLs point to the Netlify site's address (its custom domain if set).
- With **Deploy automatically** on, every change to the public site triggers a deploy about 10 seconds later. That covers changes from the admin, the REST API and AI jobs: publishing, unpublishing, editing, themes and site settings. Deploys are skipped when the export hasn't changed (editing a draft, for example), and only changed files are uploaded. Editors can also click **Deploy now**.
- To write the export to a folder for another host: `pnpm export <site-slug> [out-dir] --url https://blog.example.com`. Serve the folder at the root of a domain. `/a/<slug>` maps to `a/<slug>.html`, so the host must serve `.html` files for extensionless URLs, or apply the `_redirects` rules.

### Social sharing (LinkedIn, X, Facebook)
The **Social** tab shares published articles on LinkedIn, X and Facebook. Owners switch networks on and enter their credentials (stored encrypted, never shown again); editors can then share any published article on demand with **Post now**, optionally with their own wording.

- **LinkedIn**: an access token with the `w_member_social` scope (`w_organization_social` for a company page) and the author URN (`urn:li:person:…` or `urn:li:organization:…`). LinkedIn tokens expire after about 60 days.
- **X**: the API key and secret of your app, plus an access token and secret with Read and Write permission (OAuth 1.0a; they don't expire).
- **Facebook**: a Page access token (`pages_manage_posts`) and the Page ID.
- With **Post automatically** on, every article published afterwards (from the admin, the REST API or an AI job) is posted to each ready network about 15 seconds later, or after a pending static deploy has finished so the link works. Articles published before you turned it on are never posted. Each article is posted once per network; a failed post is shown in the list and isn't retried automatically.
- Posts link to the article under the **Site URL** you set, else the static site, the custom domain or the `BASE_DOMAIN` subdomain. Without a public address nothing is posted.
- The default text is the title, plus hashtags from the article's tags on X, and the summary on LinkedIn and Facebook. The link is attached as a link card.

### Roles
`author` can write drafts and send them for review. `editor` can also publish, edit any article and manage design. `owner` can also change settings, members and API tokens.

### REST API
```bash
curl -X POST localhost:3000/api/v1/ai/articles?wait=1 \
  -H "Authorization: Bearer cms_..." -H "Content-Type: application/json" \
  -d '{"topic":"Why cities are rediscovering trams","publish":true,"designLook":"industrial, urban"}'
```
Articles accept `imageUrl`/`imageAlt` (a cover image) and `seoTitle`/`seoDescription`. AI article requests accept `"coverImage": true`, and AI theme requests accept `"heroImage": true`.
Endpoints: `GET/POST /api/v1/articles`, `GET /api/v1/articles/:id`, `POST /api/v1/ai/articles`, `POST /api/v1/ai/themes`, `POST /api/v1/ai/seo` (`{"target":"article","articleId":1}`, `{"target":"articles"}` or `{"target":"site"}`), `GET /api/v1/jobs/:id`. Without `?wait=1`, a request returns `202` with a job to poll.
